# Deterministic circuit-spec v2 to KiCad board writer

`pcbex generate-circuit-kicad-board` closes the previously missing producer
between the deterministic circuit/schematic handoff and the existing KiCad
placement, routing, and manufacturing commands. It creates a new KiCad board
from explicit, local, digest-bound inputs; it does not use an installed KiCad
footprint library or a network service.

```sh
pcbex write-circuit-spec-kicad-schematic \
  examples/circuit-board-spec-v2.json \
  --output build/circuit-board-example.kicad_sch

pcbex generate-circuit-kicad-board \
  examples/circuit-board-spec-v2.json build/circuit-board-example.kicad_sch \
  --footprint-closure examples/circuit-board-footprint-closure-v1.json \
  --construction-profile examples/circuit-board-construction-profile-v1.json \
  --physical-profile examples/circuit-board-physical-profile-v1.json \
  --output-dir build/generated-board
```

The output directory must not already exist. A successful invocation publishes
exactly these three regular files:

- `board.kicad_pcb`: the newly constructed, placed, unrouted board;
- `board-binding.json`: the existing closed circuit/schematic/board binding
  report, freshly recomputed from the generated bytes; and
- `manifest.json`: path-free identities for every raw and normalized input and
  both retained outputs.

The complete directory is built privately and published without replacing an
existing destination. A failure before publication leaves no output directory.

## Footprint closure

The footprint closure is a closed schema-v1 JSON document. It embeds every
KiCad footprint source used by the circuit rather than naming a host library
path. Each entry binds its circuit `footprint` identifier to the decoded UTF-8
source byte count and SHA-256. Entries are unique, and their normalized form is
sorted by identifier; the set must equal the unique footprint identifiers in the normalized circuit
specification, with neither missing nor unused entries.

The parser accepts at most 256 entries, 4 MiB of decoded source per entry,
64 MiB in aggregate, and 96 MiB for the containing JSON. Each source must be
one bounded `(footprint ...)` document with exactly one format version no newer
than `20250114` and a front-copper root. Closure v1 accepts only `smd`,
`connect`, plated-through-hole, and non-plated-through-hole pads using circle,
oval, rectangle, or rounded-rectangle shapes. Pad records are limited to
validated position, size, layer, optional drill, and rounded-corner fields.
The writer strips source UUID/timestamp identities and owns the reference,
value, MPN, placement, and pad-net fields placed into the board. It intentionally
omits source text, silk/fab/courtyard graphics, and 3D models rather than
copying syntax that its self-check does not understand. A closure cannot
smuggle board nets, assigned component identity, local routing rules, model
paths, custom/trapezoid pads, or a second root document. Numbered pads must
match the complete pin-number set of every circuit part using that footprint.
The deliberately small exception is an electrically unconnected, unnumbered
non-plated mechanical hole.

These checks establish exact provenance for the caller-supplied source and the
validated pad geometry reproduced in the board. Placement uses the pad
envelope plus the declared clearance; omitted artwork and courtyard geometry
do not enlarge that envelope. The contract does not authenticate the
footprint's manufacturer, library, datasheet, dimensions, artwork, courtyard,
or electrical suitability.

## Construction and physical profiles

The board-construction profile is a separate closed schema-v1 contract. It
binds the board thickness, two to 32 copper layers, the intervening dielectric
stack, and deterministic placement/routing defaults. Copper names are fixed to
`F.Cu`, consecutively numbered internal layers, and `B.Cu`; dielectric and
copper entries alternate, all dimensions are positive integers, and the layer
thicknesses must sum to the declared board thickness. The KiCad format version
and generator identity are engine-controlled rather than caller-controlled.
The generated legacy-compatible board carries the width, clearance, and via
dimensions that KiCad's board-level net-class syntax can represent. Grid,
bend-cost, and via-cost values remain bound by the manifest and used by the
producer, but KiCad board syntax cannot carry them. `route-kicad` does not
derive any of its seven routing arguments from that board net class, so callers
must explicitly repeat the construction profile's grid, width, clearance, via
diameter, via drill, bend cost, and via cost.

The existing physical-constraint profile remains the geometry authority for
the outline, dimensions, fixed component coordinates, keepouts, and optional
manufacturing minima. Both its raw bytes and normalized digest are retained in
the manifest. The writer constructs an initial board, applies deterministic
placement under that profile, and checks fixed positions, outline bounds, and
overlap constraints before retaining output.

The v1 writer deliberately accepts only the physical subset it can reproduce
and reimport exactly: an empty outline (rendered as the full board rectangle)
or that same four-corner rectangle, front-side fixed placements at cardinal
rotations without fixed-component keepout dimensions, and track/via/zone keepout polygons on
declared copper layers. Footprint-forbidden keepouts and per-keepout minimum
track-width or clearance overrides are rejected rather than silently weakened.
The final reimport must reproduce the dimensions, outline, fixed positions, and
complete keepout set before publication. Construction routing dimensions are
also checked against every supplied manufacturing minimum.

## Electrical and publication gates

The command does not trust a retained review. It normalizes and checks the
circuit specification, imports the supplied schematic, and reruns the existing
circuit-to-schematic handoff. After footprint insertion and placement it
reimports the final board and reruns
`verify-circuit-kicad-board-binding`. Publication requires that complete
report to have `approved: true`; the retained report bytes are the same bytes
identified by the manifest. Version 1 uses pcbex's fixed default electrical
policy for this fresh handoff and board-binding replay; it does not accept a
caller-selected electrical policy.

All five caller inputs are bounded and captured before generation, and are
reread before publication. Input aliases, symlinks, replacement, an existing
output, an unsafe output parent, an unexpected staged entry, or an identity
mismatch fail closed. On Unix the canonical output parent must be owned by the
effective user and must not be group- or other-writable; that condition and the
pinned parent identity are checked before and immediately around the
no-replace rename. Windows retains real directory handles and checks identities
around its guarded rename. These checks do not protect against a concurrent
process running as the same OS principal and able to mutate the already trusted
parent. If a check or synchronization fails after the rename, the command
reports failure but the directory may already exist and must not be consumed.
The manifest contains no caller path, timestamp, random value,
installed-library result, or network result, so the same five exact inputs
produce the same three artifact byte streams across repeated invocations of the
same compiled pcbex executable on the same supported target. Cross-target
floating-point/libm identity and executable or toolchain provenance are not
claimed. Semantically equivalent but byte-different JSON remains distinguishable
through the raw source identities in the manifest.

The three public schemas are available without running the producer:

```sh
pcbex footprint-closure-schema
pcbex board-construction-profile-schema
pcbex circuit-kicad-board-manifest-schema
```

These JSON Schemas provide the closed structural preflight contract. The
runtime parser remains authoritative for UTF-8 byte ceilings, duplicate-key
rejection, canonical numeric and layer spellings, control-character rules,
cross-entry inventories, source byte/SHA checks, and the semantic relationships
between the three inputs and outputs; JSON Schema `maxLength` alone counts
characters rather than encoded bytes.

## Scope limits

The output is a deterministic, electrically bound, placed-but-unrouted board.
It is intended as input to the existing `route-kicad` command and the normal
DRC, DFM, deterministic-pipeline, manufacturing, and authorization gates.

This release does not resolve system footprint libraries, fetch supplier or
datasheet data, choose alternates, merge an existing board, preserve hand
layout, add routed tracks, vias, or copper zones, run KiCad DRC, prove signal
integrity, create manufacturing files, authenticate a toolchain, authorize
fabrication or procurement, or place an order. Hierarchical/bus/multi-unit
designs and arbitrary KiCad project
sidecars remain outside the flat circuit-spec-v2 writer boundary. MCP and
Action parity are also deferred; v1.463 is a CLI-only producer.
